## 2. Intent

Make the registry able to answer two questions the Accelerate Tanzania team must answer before it can publish anything:

1. **Where did this record come from** — the actor submitted it, or the team curated it?
2. **On what basis is it publishable** — how was consent obtained, when, and against what evidence?

This is the data foundation the other three chunks stand on. It ships value alone: even with no self-registration portal, the AT team gains the two tracking columns Daniela asked for, plus the provenance that makes a `GRANTED` flag defensible.

## 3. Problem / Current Behavior

- **`consentStatus` is a flag with no evidence behind it.** `GRANTED` / `DENIED` / `UNKNOWN` gates publication (TRD ADR-004) but records nothing about *how* consent was obtained. For the Excel track — where consent is collected by email or signed form, entirely outside the platform — a bare `GRANTED` is an unauditable assertion. If a published actor later disputes it, there is nothing to point at.
- **Nothing distinguishes the two tracks.** The client explicitly asked to "clearly identify which actors will self-register through the portal and which ones will be uploaded from the Excel file." There is no field for that, so it currently lives only in a side spreadsheet.
- **The trader taxonomy is too narrow for the incoming data.** `TRADER_TYPES` has 6 values; the new `Partner Profile 14.4.2026.xlsx` carries humanitarians/INGOs, digital service providers, QDS seed producers, and bulk buyers. Roughly 590 of ~1,318 rows would quarantine on `traderType` alone.

## 4. Proposed Outcome

1. Each `Actor` carries **`registrationSource`** — `TEAM_MANAGED` (default) or `SELF_REGISTERED`.
2. Each `Actor` carries **consent provenance**: `consentMethod`, `consentObtainedAt`, `consentReference`.
3. The **admin actors console** shows and filters on both, and the admin create/edit form captures them.
4. The **import template** gains the matching columns (Daniela's two requested columns, plus provenance), with a `TEMPLATE_VERSION` bump and a regenerated byte-stable asset.
5. The **trader taxonomy** grows to 10 canonical types, with source-value aliases for the spellings actually present in the client workbook.
6. **Admin export** carries the new fields so the team can track consent from the export rather than a side file.

## 5. Scope

**Data (additive migration only):**

```prisma
enum RegistrationSource {
  TEAM_MANAGED     // curated/imported by the Accelerate Tanzania team
  SELF_REGISTERED  // submitted by the actor through the portal
}

enum ConsentMethod {
  NOT_RECORDED     // default — no evidence captured yet
  PORTAL_CHECKBOX  // accepted in the self-registration flow (chunk 3)
  SIGNED_FORM      // countersigned document on file
  EMAIL            // written email confirmation
  VERBAL_FIELD     // recorded by an enumerator during field collection
}

model Actor {
  // ... existing fields unchanged ...
  registrationSource RegistrationSource @default(TEAM_MANAGED)
  consentMethod      ConsentMethod      @default(NOT_RECORDED)
  consentObtainedAt  DateTime?
  consentReference   String?            // file name, email message id, or REG-… reference

  @@index([registrationSource])
}
```

**Backend:**
- Prisma migration (additive; existing rows take the defaults).
- `ActorCreateDto` / `ActorUpdateDto` accept the four fields, validated (`@IsEnum`, `@IsDateString`, length-bounded reference).
- **Consistency rule:** `consentStatus = GRANTED` requires `consentMethod ≠ NOT_RECORDED` **and** a non-null `consentObtainedAt`. Enforced in the DTO/service, not the UI.
- `admin-actor.serializer.ts` exposes all four; `role-aware.serializer.ts` exposes **none** (see §7).
- `common/normalize.ts` — extend `TRADER_TYPES` with `humanitarian`, `digital_service_provider`, `qds_producer`, `bulk_buyer`, plus aliases (`INGO`, `NGO/INGO`, `Digital Service Provider`, `QDS`, `cbo`, `Bulk buyer`, …).
- `common/template-columns.ts` — new columns; bump `TEMPLATE_VERSION` to `v2`; regenerate the asset (`npm run generate:template`).
- `actor-import.service.ts` — parse the new columns, apply the same consistency rule, keep `UNKNOWN` as the import default.
- Audit: the four fields appear in the `ActorAuditLog` diff like any other tracked field (no new action needed).

**Frontend:**
- Admin actors table: a **Source** column and a **Consent** column that shows status *and* method; filters for both.
- Admin actor create/edit form: a "Consent & provenance" fieldset (status · method · date · reference) with the consistency rule surfaced as inline validation.
- Export column additions.

**Infra:** none.

## 6. Non-Goals

- **The public registration form and the review queue** — chunks 3 and 4.
- **Mapping the 8-sheet workbook** — chunk 2. This spec only makes the taxonomy and template *able* to receive it.
- **Backfilling consent evidence for existing records.** The migration defaults every existing row to `TEAM_MANAGED` / `NOT_RECORDED` and leaves it there. Populating real provenance is an AT-team data task, not a code change — and inventing values would be exactly the integrity failure R-4 warns about.
- **Changing what `Public` can see.** No public-facing behavior changes at all.
- **Storing the consent document itself** (no file upload / S3 evidence store). `consentReference` is a text pointer to where the evidence lives.
- **Re-litigating `ConsentStatus`.** The existing enum and the ADR-004 `WHERE`-pinning stay exactly as they are.

### PII determination (must be settled during `/akili-specify`)

The four new fields are **not** added to `PII_ALLOWLIST` and **not** exposed publicly, on this reasoning: `consentReference` may name a person or an email thread; `consentMethod`/`consentObtainedAt` describe an internal governance process; `registrationSource` reveals nothing useful publicly and could imply a quality judgement about a record. **Admin-only by construction** is both safer and simpler than arguing each field's sensitivity.

`pii-boundary.spec.ts` must be extended to assert none of the four appears on any public read path. That test staying green is a **release gate**.

## 9. Approach Options

| | **A — Fields on `Actor` (recommended)** | **B — Separate `ConsentRecord` table** | **C — `Json` provenance blob** |
|---|---|---|---|
| Shape | 4 columns + 2 enums on `Actor` | 1:N history of consent events | One `consentMeta Json` column |
| Consent history | Only the current state | Full history (grant → withdraw → re-grant) | Only current, unvalidated |
| Query/filter/export | Native, indexed | Needs a join on every admin read | Not filterable in MySQL without pain |
| Migration risk | Additive, trivial | New model + FK + import/audit rework | Additive but type-unsafe |
| Effort | ~0.5 wk | ~1.5 wk | ~0.4 wk |

## 10. Recommended Approach

**Option A.** Consent here is a *current-state* fact ("is this actor publishable, and on what basis"), not an event stream — and the event stream that *does* matter is already covered: `ActorAuditLog` records every consent-field change with actor, admin, timestamp, and diff. Option B would build a second, partly redundant history at three times the cost. If a regulator later demands a first-class consent ledger, the audit log is the migration source and Option A's columns become its projection.

**Assumption A-1 (cheap to reverse):** `consentReference` is free text, not a foreign key to a document store. If the program wants uploaded evidence files, that is a follow-up spec — the column becomes the S3 key.

## 11. Risks, Dependencies, And Open Questions

| ID | Risk | Mitigation |
|---|---|---|
| **R-1** | The **consistency rule breaks existing data**: rows that are already `GRANTED` will have `NOT_RECORDED` / null date and would fail the new validation on their next edit. | Enforce the rule on **write of `GRANTED`**, not on read or on unrelated updates, and ship a one-off admin report listing `GRANTED`-without-provenance rows for the AT team to resolve. Never auto-fill. |
| **R-2** | **Template regeneration is byte-stability-sensitive** — a committed asset is asserted against by test. A careless regeneration turns a green suite red for reasons unrelated to the change. | Follow `backend/CLAUDE.md`: change columns → bump `TEMPLATE_VERSION` → `npm run generate:template` → commit the asset. Verify `generate-template.spec.ts` in the same task. |
| **R-3** | **Taxonomy churn.** Adding four trader types touches map filters, directory chips, and the crop/type legend; a type with no colour or label renders as a gap. | Treat the frontend type-label/colour map as part of this spec's scope, not an afterthought. |
| **R-4** | `qds_producer` may be the **wrong abstraction** — a QDS producer is arguably a role in seed multiplication, not a trading type. | See OQ-1. Decide before the migration; renaming an enum value afterwards is a data migration. |
| **OQ-1** | Should `humanitarian` and `digital_service_provider` be trader *types*, or a separate `sector`/`category` dimension? Overloading `traderType` is expedient but will strain if the workbook grows more categories. | Resolve during `/akili-specify` with `software-architect`. A second dimension is cheap **now** and expensive later. |
| **OQ-2** | Is `VERBAL_FIELD` consent legally sufficient for publication, or should it be admissible for the record but blocked from `GRANTED`? | Program/legal. Affects one validation branch. |

## 12. Success Criteria

- Migration applies to the dev RDS with **zero data loss**; every pre-existing actor reads back as `TEAM_MANAGED` / `NOT_RECORDED`.
- An Admin can set consent status, method, date, and reference on an actor, and `GRANTED` is rejected with a field-level error when method or date is missing.
- An admin export contains the four new columns; a `Public` export and every public read path contain **none** of them.
- A template downloaded after this ships has the new columns and imports cleanly; a `v1` template produces a clear "please re-download" message, not a parse error.
- All 590-odd workbook rows whose type is one of the four new categories normalise to a canonical value instead of quarantining (verified against a sample, not the full file — the full run is chunk 2).
- Gates green: `npm test`, `npm run build`, `npx eslint … --quiet` in `backend/`; `npm test`, `npm run lint`, `npm run build` in `frontend/`; `pii-boundary.spec.ts` green.
